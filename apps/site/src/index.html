Features

Everything you need. Nothing it can see.

The parts of a password manager you use every day, built on the assumption that the server is the first thing an attacker would go after.

Encrypted on your device

AES-256-GCM with a fresh nonce for every write. Keys are derived in the browser and never cross the network.

Names and tags too

Not just passwords. Entry names, usernames, websites, notes and tags are all encrypted, so a stolen database does not even list which sites you use.

Two-factor codes built in

Store authenticator keys alongside the login they belong to and get live one-time codes, generated locally to the RFC 6238 standard.

Strong passwords, generated

A generator drawing from the browser's cryptographic random source, with a strength meter on every password you save.

Copy that cleans up

Copy a username, password or code in one click. Secrets are cleared from the clipboard after thirty seconds.

Locks itself

Keys live in memory only — never in browser storage or cookies. Close the tab, reload, or step away for fifteen minutes and the vault is locked.

How it works

Your password never leaves the browser

The server checks that you are you without ever learning the secret that proves it.

You type your master password

Your browser stretches it with 600,000 rounds of PBKDF2 into a master key. That pause before the vault opens is the same pause an attacker pays for every guess.

On your device

Two keys split off

One key unlocks your vault and stays put. A second, separate key — one that cannot be worked back to the first — is what the server sees to confirm it is you.

On your device

Only ciphertext is stored

Entries are sealed before upload. The server keeps encrypted blobs and a hash of the login key. A full breach of it yields nothing readable.

On the server
What the server holds

Built so a breach is boring

What the server stores

  • Encrypted entries it holds no key for
  • A hash of your login key — not of your password
  • Your vault key, locked with keys only you can derive
  • Your email as a keyed hash, not in plain text

What it never sees

  • Your master password
  • Your recovery key
  • The names of the sites you use
  • Any password, note, or code in your vault

There is no password reset. That is the point.

Because the server cannot read your vault, it cannot let you back in either. When you sign up you get a recovery key, shown once and never sent anywhere. It is the only other way in. Keep it somewhere safe and offline.

Lose both the master password and the recovery key, and nobody — including whoever runs the server — can open the vault.

FAQ

Questions worth asking

If the server is hacked, what does the attacker get?

Encrypted entries, a hash of each user's login key, and vault keys that are themselves encrypted. To read anything they would have to guess a master password, paying 600,000 rounds of key stretching per guess, per account.

Why does unlocking take a second?

That is the key stretching happening on your device. It is deliberately slow, so that guessing passwords is slow too.

Why don't my entries show website icons?

Fetching an icon means asking someone else's server for it, which tells them which sites you have accounts with. Vault shows a coloured initial instead and makes no request to any third party.

Why do I have to unlock again after reloading the page?

Your keys are kept in memory and nowhere else — not in local storage, not in a cookie. A closed tab leaves nothing behind for someone with your laptop to find.

Does the page load anything from other companies?

No. No analytics, no fonts, no CDNs, no trackers. A strict Content-Security-Policy blocks the page from loading anything that does not come from this server.

Is there anything it does not protect against?

Yes, and it is stated plainly on the security page: a web app is only as trustworthy as the code it is served, and today that rests on a free dynamic-DNS name.
